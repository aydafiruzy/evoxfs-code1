# راهنمای کار با Git و GitHub برای پروژه‌ی EvoX-FS

این راهنما برای کسی است که تا حالا با Git کار نکرده. لازم نیست همه‌اش را یک‌جا یاد بگیری. بخش ۱ و ۲ برای شروع کافی است.

---

## ۱. پنج مفهوم اصلی

| مفهوم | یعنی چه؟ | مثال در پروژه‌ی تو |
|---|---|---|
| **Repository (ریپو)** | پوشه‌ی پروژه، همراه با تاریخچه‌ی کامل همه‌ی تغییرها | `evoxfs-code1` |
| **Commit** | یک «عکس» از پروژه در یک لحظه، همراه با یک پیام که می‌گوید چه چیزی عوض شده | «وزن اندازه در Classic DE از 0.4 به 0.1 تغییر کرد» |
| **Branch (شاخه)** | یک نسخه‌ی موازی برای امتحان کردن یک تغییر، بدون خراب کردن نسخه‌ی اصلی (`main`) | `fix-shap-term` |
| **Pull Request (PR)** | درخواست اینکه تغییرات یک شاخه به `main` اضافه شود. جایی است که تغییرات را می‌بینی، بررسی می‌کنی و نظر می‌دهی | همین PR که این ساختار جدید را آورده |
| **Tag** | یک اسم ثابت روی یک commit مهم، مثل «نسخه‌ای که نتایجش را به استاد دادم» | `v1.0`، `v1.1` |

**قانون طلایی:** هر نتیجه‌ای که به استاد نشان می‌دهی باید معلوم باشد از کدام نسخه‌ی کد آمده. برای همین در `EXPERIMENTS.md` نسخه‌ی کد (tag یا commit) را می‌نویسی.

## ۲. روال کار روزانه (فقط با سایت GitHub، بدون نصب چیزی)

### الف) تغییر یک تنظیم (مثلاً وزن fitness)
1. در GitHub برو به `configs/base.yaml`.
2. روی آیکون مداد (✏️ Edit) بزن.
3. مقدار را عوض کن، مثلاً `size: 0.40` ← `size: 0.10`.
4. پایین صفحه، در **Commit message** بنویس چه کردی و چرا، مثلاً: `Classic DE: size weight 0.4 -> 0.1 (common value)`.
5. گزینه‌ی **Create a new branch** را انتخاب کن و اسمی بده (مثلاً `classic-weight-01`)، بعد **Propose changes** را بزن.
6. صفحه‌ی **Pull Request** باز می‌شود. **Create pull request** را بزن.
7. وقتی مطمئن شدی، **Merge pull request** را بزن تا تغییر به `main` برود.

### ب) اجرای آزمایش در Colab
1. در Colab: File ← Open notebook ← تب **GitHub** ← بنویس `aydafiruzy/evoxfs-code1` ← فایل `notebooks/run_experiment.ipynb`.
2. در سلول اول `DATASET` را انتخاب کن. اگر می‌خواهی یک نسخه‌ی خاص را اجرا کنی، `REPO_BRANCH` را هم تنظیم کن (مثلاً `"v1.0"` یا اسم شاخه).
3. Runtime ← Run all.
4. **نوت‌بوک را در ریپو ذخیره نکن** (کد اصلی در `src/` است). نتایج خودکار روی Drive ذخیره می‌شوند.

### ج) ثبت آزمایش در `EXPERIMENTS.md`
بعد از هر اجرای مهم، یک خط به جدول اضافه کن (همان روش ویرایش در بخش الف):
تاریخ، دیتاست، نسخه‌ی کد، چه چیزی عوض شده، نتیجه‌ی اصلی، و اسم پوشه‌ی Drive.

### د) گذاشتن tag روی نسخه‌ای که به استاد می‌دهی
1. در صفحه‌ی ریپو، سمت راست، روی **Releases** ← **Create a new release** بزن.
2. در **Choose a tag** اسم جدید بنویس، مثلاً `v1.1`.
3. یک توضیح کوتاه بنویس («SHAP term changed to mean») و **Publish release** را بزن.

## ۳. ساختار ریپو: هر چیز کجاست؟

| پوشه یا فایل | چه چیزی در آن هست | کی تغییرش می‌دهی؟ |
|---|---|---|
| `configs/` | همه‌ی عددها: وزن‌ها، بودجه، اندازه‌ی جمعیت | برای هر آزمایش جدید |
| `src/evoxfs/` | خود الگوریتم (یک بار نوشته شده، برای همه‌ی دیتاست‌ها) | وقتی روش را عوض می‌کنی (مثلاً فرمول SHAP) |
| `notebooks/run_experiment.ipynb` | فقط اجرا: دیتاست را انتخاب می‌کنی و Run all | تقریباً هیچ‌وقت |
| `notebooks/archive/` | نوت‌بوک‌های اصلی اکتبر ۲۰۲۶ با خروجی‌هایشان | هیچ‌وقت (فقط برای مرجع) |
| `EXPERIMENTS.md` | دفترچه‌ی آزمایش‌ها | بعد از هر اجرا |
| `README.md` | معرفی پروژه و جدول نتایج اصلی (اولین چیزی که استاد می‌بیند) | وقتی نتیجه‌ی اصلی عوض می‌شود |
| `tests/` | بررسی خودکار اینکه کد درست کار می‌کند | فقط وقتی `src` را عوض می‌کنی |

**چرا کد مشترک؟** قبلاً سه نوت‌بوک تقریباً یکسان داشتی. اگر یک باگ را درست می‌کردی، باید سه جا عوضش می‌کردی و ممکن بود یکی جا بماند. حالا الگوریتم فقط یک جا (`src/evoxfs/`) نوشته شده است.

## ۴. پیام commit خوب

| ❌ بد | ✅ خوب |
|---|---|
| `update` | `fitness: SHAP term uses mean instead of sum` |
| `Add files via upload` | `Add sonar results table to README` |
| `fix` | `Fix: sensitivity uses population 20 (was 10)` |

یک خط کوتاه که بگوید **چه چیزی** عوض شد. اگر لازم بود، در خط بعد بنویس **چرا**.

## ۵. قدم بعدی (اختیاری): GitHub Desktop

وقتی با روش سایت راحت شدی، برنامه‌ی [GitHub Desktop](https://desktop.github.com) را نصب کن. با آن می‌توانی ریپو را روی لپ‌تاپ داشته باشی و فایل‌ها را با هر ویرایشگری (مثلاً VS Code) عوض کنی. بعد در برنامه پیام commit را می‌نویسی، **Commit** و بعد **Push** را می‌زنی. مفاهیم دقیقاً همان‌هایی است که بالا گفته شد.

## ۶. ابزارهای دیگر که دانشجوها استفاده می‌کنند

- **Weights & Biases** یا **MLflow**: ثبت خودکار نتایج هر اجرا و مقایسه‌ی نمودارها (برای دانشجو رایگان است). وقتی تعداد آزمایش‌ها زیاد شد، مفید است.
- **Overleaf**: نوشتن مقاله یا پایان‌نامه با LaTeX. می‌شود استاد را هم به پروژه اضافه کرد.
- **Zotero**: مدیریت مقاله‌ها و منابع.
